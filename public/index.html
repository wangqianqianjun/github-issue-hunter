快速配置说明

          

            

              
1) 全局配置

              
`工作目录` 是 Issue Hunter 的运行根目录，用于保存运行状态和每个 issue 的产物，不是代码仓库目录。

              
`全局并发` 控制“所有仓库总共”同时运行的任务数，建议先用 `1~2`。

            

            

              
2) 仓库配置

              
只填本地仓库路径。owner/repo 通过 `gh repo view` 自动识别，无需手填。

              
三条 wording 是写回 issue 的固定回复文案，可按团队风格调整。

            

            

              
3) Slack 配置（可选）

              
最小只需 `Bot Token(xoxb-) + App Token(xapp-)`。

              
未配置 Slack 时，issue 拉取与自动处理仍可独立运行。

Slack 配置向导

          

            
最小必填：Bot Token(`xoxb-`) + App Token(`xapp-`)。

            
推荐模式：勾选 Socket Mode（本地直连 Slack，无需公网 webhook）。

            
重要：先把 Bot 邀请进目标频道，再刷新频道列表进行仓库绑定。

频道绑定仓库

          
先拉取频道列表，再为每个仓库选择 Slack 频道与通知方式。

          

            
Transport 说明：`chat_sdk` 推荐（Thread 体验更完整）；`slack_sdk` 为直发 API；`none` 表示不发 Slack。

            
通知开关：仅控制该仓库是否向 Slack 推送，不影响 issue 自动处理主流程。
